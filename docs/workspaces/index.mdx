工作空间界面是对任务执行体验的全新设计，提供了一个专为 AI 辅助开发工作流优化的类 IDE 界面。

## 什么是工作空间？

**工作空间**是一个用于完成编码任务的隔离环境。可以把它想象成一个专属的"项目工作室"，你在这里：

1. **专注于特定任务** - 每个工作空间聚焦一个目标（例如"添加用户认证"）
2. **与编码 Agent 对话** - AI 助手为你编写和修改代码
3. **审查变更** - 查看具体添加、修改或删除了哪些代码
4. **测试应用** - 内置预览浏览器，实时查看变更效果
5. **创建 Pull Request** - 准备就绪后提交变更供审查

<Info>
**为什么要使用工作空间而不是手动编码？**

工作空间让你用自然语言描述想要什么，AI 编码 Agent 负责实现。你审查变更、提供反馈、反复迭代，直到任务完成。这就像拥有一个瞬间完成工作且永不疲倦的开发伙伴。
</Info>

## 核心概念

| 概念 | 描述 | 示例 |
|------|------|------|
| **工作空间** | 你与 Agent 协作的任务执行环境 | "添加用户认证" |
| **仓库** | 工作空间中包含的 Git 仓库 | `frontend`、`backend` |
| **会话** | 与编码 Agent 的对话线程 | 用于实现功能的 Claude Code 会话 |

**它们的关系：**
- **工作空间**是你针对特定任务的工作环境
- 一个工作空间可以包含一个或多个**仓库**（每个仓库有独立的 Git 状态）
- 在工作空间中，你可以有多个**会话**来与不同的 Agent 对话或开始新的对话

例如，你可以创建一个"添加认证"的工作空间，同时包含 `frontend` 和 `backend` 仓库。在该工作空间中，你可能有一个会话用于实现后端 API，另一个会话用于前端 UI。

## 常见问题

<AccordionGroup>
<Accordion title="创建工作空间时我的代码会发生什么？">
创建工作空间时，Vibe Kanban 会：

1. 创建一个 **Git worktree** - 一个关联到新分支的独立工作目录
2. 你的原始仓库保持不变
3. 所有变更都在新分支上的 worktree 中进行
4. 在你明确创建 PR 之前，不会推送到远程仓库

**你的主分支是安全的。** 工作空间会隔离所有变更，直到你准备好合并。
</Accordion>

<Accordion title="我可以同时处理多个任务吗？">
可以。每个工作空间完全独立：

- 创建任意数量的工作空间
- 每个工作空间有自己的分支、变更和会话
- 使用侧边栏在工作空间之间切换
- 不同工作空间中的 Agent 互不干扰
</Accordion>

<Accordion title="如果 Agent 犯了错误怎么办？">
你拥有完全控制权：

- **审查变更** - 在提交前在变更面板中查看
- **添加注释** - 在特定行上请求修复
- **编辑消息** - 用不同的指令重试
- **启动新会话** - 如果对话偏离方向
- **删除工作空间** - 如果你想完全重新开始

Agent 只修改工作空间中的文件 - 未经你的明确操作，它无法推送代码或合并。
</Accordion>

<Accordion title="我怎么知道 Agent 完成了？">
注意以下指标：

- **侧边栏状态**从"运行中"变为"空闲"
- **聊天显示完成**消息或询问下一步
- **变更面板**显示所有已做的修改

如果 Agent 需要你的输入（审批、澄清），你会看到"需要关注"指示器和举手图标。
</Accordion>

<Accordion title="项目和工作空间有什么区别？">
- **项目** = 将相关仓库分组的容器（在设置中一次性配置）
- **工作空间** = 针对特定编码任务的任务执行环境

可以这样理解：项目就像一个包含你仓库的团队文件夹。工作空间是使用这些仓库进行的一项任务。
</Accordion>
</AccordionGroup>

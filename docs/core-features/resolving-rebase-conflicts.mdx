## 当你看到"Rebase Conflicts"时

点击 rebase 按钮后，如果你的更改与基础分支有冲突，任务状态会变为"Rebase conflicts"并出现冲突解决横幅。

<Frame>
<img src="/images/vk-rebase-conflicts-top.png" alt="任务显示 rebase 冲突状态和冲突解决选项" />
</Frame>

冲突横幅提供了三种解决方式：

<Frame>
<img src="/images/vk-rebase-banner.png" alt="冲突解决横幅，显示三个可用选项" />
</Frame>

- **Resolve Conflicts** - 自动生成解决指令给编程代理
- **Open in Editor** - 手动编辑冲突文件
- **Abort Rebase** - 取消并返回之前的状态

## 自动解决冲突

最简单的方法是让编程代理自动解决冲突：

1. 从冲突横幅中点击 **Resolve Conflicts**，生成针对你的冲突情况量身定制的指令，并将其插入到后续消息区域。

2. 查看生成的指令，然后点击 **Resolve Conflicts**（发送按钮会变为这个），让代理分析冲突文件并自动完成 rebase。

<Frame>
<img src="/images/vk-rebase-conflicts-prompt.png" alt="冲突解决横幅，后续消息字段中显示自动生成的指令" />
</Frame>

代理完成解决后，你的任务状态会显示领先 *n* 个提交，**Merge** 按钮会再次可用。

## 手动解决（替代方案）

如果你更愿意手动解决冲突，有两个选择：

**单个文件**：从冲突横幅中使用 **Open in Editor** 一次编辑一个冲突文件。解决并刷新页面后，你可以再次点击该按钮处理下一个文件。

**多个文件（推荐）**：点击任务右上角的三点图标并选择 **Open in [Your IDE]**，在你选择的 IDE 中打开所有 worktree 文件，可以一次性解决所有冲突。

<Steps>
<Step title="打开 IDE">
  点击右上角的三点图标并选择 **Open in [Your IDE]** 来访问所有 worktree 文件，或从横幅中使用 **Open in Editor** 处理单个文件。
</Step>

<Step title="编辑冲突文件">
  解决每个文件中的合并标记：
  
  ```diff
  <<<<<<< HEAD (your changes)
  function newFeature() {
    return "new implementation";
  }
  =======
  function oldFeature() {
    return "existing implementation";
  }
  >>>>>>> main (base branch changes)
  ```
</Step>

<Step title="继续 rebase">
  编辑完所有冲突后，暂存并继续：
  
  ```bash
  git add .
  git rebase --continue
  ```
</Step>
</Steps>

<Tip>
自动解决适用于大多数冲突。仅在你需要精确控制合并决策时才使用手动解决。
</Tip>

## 中止 Rebase

如果你需要完全取消 rebase，点击 **Abort Rebase** 返回到"Rebase needed"状态。然后你可以再次尝试 rebase 或从更新的基础分支创建新的任务尝试。

## Rebase 到不同的基础分支

如果你更改了任务尝试的基础分支，并看到与你更改无关的提交，你可以使用 `git rebase --onto` 仅将你的工作 rebase 到新的基础分支上：

```bash
git rebase <last-commit-before-your-work> --onto <new-base>
```

### 示例场景

你不小心从 `develop` 分支创建了任务尝试，但它应该基于 `main` 分支。在任务设置中将基础分支更改为 `main` 后，你会看到来自 `develop` 的不属于你工作的提交：

```bash
# 找到你工作开始前的最后一个提交（例如在 git log 中）
# 然后仅将你的提交 rebase 到 main 上
git rebase 64d504c94d076070d17affd3f84be63b34515445 --onto main
```

此命令会提取你的提交（指定提交哈希之后的所有内容），并将它们重新应用到 `main` 上，排除来自 `develop` 的无关提交。

<Warning>
谨慎使用 `git rebase --onto`。确保你识别了正确的提交哈希——即不属于你当前任务的最后一个提交。建议先创建备份分支：`git branch backup-branch`。
</Warning>

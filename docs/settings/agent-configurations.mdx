<Info>
Agent 配置文件通过表单界面进行配置。选择一个 Agent，然后创建或编辑配置变体以自定义其行为。
</Info>

<Info>
Agent 配置文件在 Vibe Kanban 中所有运行 Agent 的地方都会使用：初始化、默认设置、创建尝试和后续操作。默认配置会预选在聊天输入框的 Agent 下拉菜单中。
</Info>

## 常见用例

| 用例 | 示例配置 |
|----------|----------------------|
| **快速迭代** | 禁用规划模式，使用更快的模型 |
| **复杂任务** | 启用规划模式，使用高级模型 |
| **自主工作** | 跳过权限提示（请谨慎使用） |
| **代码审查** | 对所有更改启用审批 |
| **多实例** | 启用 Claude Code Router 进行并行工作 |

## 核心概念

理解以下概念有助于你有效配置 Agent：

<AccordionGroup>
<Accordion title="Planning Mode（规划模式）">
启用后，Agent 会在编写代码之前先创建详细的计划。这会增加一个额外的步骤，让你在实施开始之前审查和批准方案。适用于需要验证策略的复杂任务，但对于简单的更改会增加额外开销。
</Accordion>

<Accordion title="Permission Prompts（权限提示）">
Agent 在执行潜在破坏性操作（如删除文件、运行 Shell 命令或修改系统配置）之前会请求权限。跳过这些提示（`dangerously_skip_permissions`）允许完全自主操作，但会移除安全保护。
</Accordion>

<Accordion title="Claude Code Router（路由器）">
将请求分发到多个并行运行的 Claude Code 实例。适用于同时处理多个任务或希望通过负载均衡来减少等待时间的情况。
</Accordion>

<Accordion title="Sandbox Modes（沙箱模式，Codex）">
控制 Agent 可以访问的内容：
- **read-only** - 可以读取文件但不能修改任何内容
- **workspace-write** - 可以修改项目目录中的文件
- **danger-full-access** - 不受限制的文件系统访问
</Accordion>

<Accordion title="Approval Levels（审批级别）">
决定 Agent 何时暂停以等待你的确认：
- **untrusted** - 每次操作前都会询问
- **on-failure** - 仅在出现问题时询问
- **on-request** - 仅在被明确要求时询问
- **never** - 完全自主（无需确认）
</Accordion>

<Accordion title="Reasoning Effort（推理强度）">
控制模型在响应之前花费多少计算"思考"能力。更高的推理会产生更全面的分析，但需要更长时间和更多 Token。较低的推理速度更快，但可能会忽略复杂问题中的细节。
</Accordion>
</AccordionGroup>

## 访问配置

通过工作区界面中的 **Settings → Agents** 访问 Agent 配置文件。

<Frame>
<img src="/images/settings-agents.png" alt="Agent configuration form editor interface with finder-style layout" />
</Frame>

界面采用 Finder 风格的双栏布局：

- **左栏** - 列出所有可用的 Agent
- **右栏** - 列出所选 Agent 的配置

## 管理配置

### 创建新配置

1. 点击 Configurations 列中的 **+** 按钮

<Frame>
<img src="/images/settings-agents-create-button.png" alt="Configuration column showing the + button with Create new tooltip" />
</Frame>

2. 输入**配置名称**（如 PRODUCTION、DEVELOPMENT）
3. 可选择一个配置进行**克隆**，或从空白开始
4. 点击 **Create Configuration**

<Frame>
<img src="/images/settings-agents-create-dialog.png" alt="Create New Configuration dialog with name field and clone option" />
</Frame>

### 编辑配置

1. 从左栏选择一个 Agent
2. 从右栏选择一个配置
3. 在下方的表单中编辑设置
4. 点击底部栏中的 **Save**

### 删除配置

1. 选择要删除的配置
2. 点击删除按钮
3. 确认删除

<Warning>
你不能删除 Agent 的唯一配置。每个 Agent 必须至少有一个配置。
</Warning>

### 设置默认配置

点击配置旁边的 **Default** 徽章，将其设为该 Agent 的默认配置。默认配置：

- 在创建新尝试时预选在 Agent 下拉菜单中
- 用于工作区中的后续消息
- 在聊天输入工具栏中显示为当前的 Agent/变体

## 环境变量

每个 Agent 配置文件可以定义环境变量，在启动时注入到 Agent 进程中。这对于将 Agent 指向非默认的 API 端点、提供 API 密钥或通过第三方提供商运行 Claude Code 非常有用。

在 Agent 配置表单的**环境变量**部分设置环境变量。

<Frame>
<img src="/images/settings-agents-env-vars.png" alt="Agent configuration form showing the Environment Variables section with KEY and value inputs" />
</Frame>

<Info>
配置文件的环境变量会覆盖 Shell 中已设置的变量。这意味着你可以保留默认的 Anthropic 凭证用于正常使用，并创建指向不同提供商的独立配置文件——每个配置文件完全隔离。
</Info>

### 通过 Claude Code 使用第三方提供商

许多提供商提供 OpenAI 兼容或 Anthropic 兼容的 API。你可以通过创建带有正确环境变量的专用配置文件来配合 Claude Code 使用它们。

<Tabs>
<Tab title="Z.ai (GLM)">
创建一个名为 **GLM**（或任何名称）的配置文件并设置：

| 变量 | 值 |
|----------|-------|
| `ANTHROPIC_BASE_URL` | `https://api.z.ai/api/anthropic` |
| `ANTHROPIC_AUTH_TOKEN` | 你的 Z.ai API 密钥 |

Z.ai 会自动将 Claude 模型映射为 GLM 等效模型，因此无需覆盖模型。

详情请参阅 [Z.ai 手动配置指南](https://docs.z.ai/devpack/tool/claude#manual-configuration)。
</Tab>

<Tab title="OpenRouter">
创建一个名为 **OPENROUTER** 的配置文件并设置：

| 变量 | 值 |
|----------|-------|
| `ANTHROPIC_BASE_URL` | `https://openrouter.ai/api` |
| `ANTHROPIC_AUTH_TOKEN` | 你的 OpenRouter API 密钥 |
| `ANTHROPIC_API_KEY` | `""`（空字符串） |

将 `ANTHROPIC_API_KEY` 设置为空字符串可防止 Claude Code 回退到 Anthropic 的服务器。

详情请参阅 [OpenRouter Claude Code 集成指南](https://openrouter.ai/docs/guides/guides/claude-code-integration)。
</Tab>

<Tab title="自定义 / 自托管">
对于任何 Anthropic 兼容的端点，请参考你的提供商文档以获取所需的环境变量。常见变量包括：

| 变量 | 用途 |
|----------|---------|
| `ANTHROPIC_BASE_URL` | 提供商的 API 端点 |
| `ANTHROPIC_AUTH_TOKEN` | 认证令牌 |
| `ANTHROPIC_API_KEY` | API 密钥（如果使用 `AUTH_TOKEN`，请设置为 `""`） |
</Tab>
</Tabs>

<Tip>
你的原始 Anthropic 配置保持不变。创建工作区时从 Agent 下拉菜单中选择 **GLM**、**OPENROUTER** 或自定义配置文件来使用第三方提供商，切换回 **DEFAULT** 配置文件即可恢复正常的 Anthropic 使用。
</Tip>

当你的任务完成后，Vibe Kanban 提供集成的 Git 操作来保持你的分支最新，并将你的工作合并回基础分支。

## Git 操作栏

在 diff 视图的顶部，你会看到重要的分支信息和操作按钮：

<Frame>
<img src="/images/vk-diff-header.png" alt="显示分支信息和操作按钮的 diff 头部" />
</Frame>

**分支信息：**
- **任务分支**：你的任务正在工作的分支
- **目标分支**：你将要合并到的分支（点击齿轮按钮可以更改）
- **领先提交数**：你的分支中目标分支没有的提交数量
- **落后提交数**：目标分支中你还没有的提交数量（当大于 0 时会启用 rebase 按钮）

**操作：**
- **Merge**：将你的更改合并到目标分支
- **Create PR**：在 GitHub 上创建 pull request
- **Rebase**：使用目标分支的最新更改更新你的分支

## Rebase

点击 **Rebase** 可以使用目标分支的最新更改来更新你的分支。这可以保持你的分支最新并维护清晰的历史记录。

如果发生冲突，请参阅[解决 Rebase 冲突](/core-features/resolving-rebase-conflicts)。

## Merge

点击 **Merge** 可以将你完成的工作合并到目标分支。你的任务将自动移动到 **Done** 列。分支在你手动删除之前会一直保留。

<Tip>
如果你正在使用 GitHub，建议创建 pull request 而不是直接合并。这样可以进行团队代码审查和 CI 检查。
</Tip>

## Pull Request 管理

### 创建 Pull Request

点击 **Create PR** 可以在 GitHub 上创建 pull request。标题和描述会从你的任务详情中自动填充。

<Frame>
<img src="/images/vk-pr-open.png" alt="创建 pull request 后显示禁用的 Push 按钮的头部" />
</Frame>

创建 PR 后，按钮会变为 **Push**（在你做出更多更改之前会处于禁用状态）。

### 更新 Pull Request

当你在创建 PR 后继续工作时，**Push** 按钮会变为可用状态。点击它可以将最新的更改推送到 pull request。

<Frame>
<img src="/images/vk-pr-with-push.png" alt="显示启用状态的 Push 按钮以及准备推送的新更改的头部" />
</Frame>

当你的 PR 在 GitHub 上被合并后，你的任务会自动移动到 **Done**。

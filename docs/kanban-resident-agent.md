# Kanban 常驻助手 Agent 需求文档

## 1. 概述

### 1.1 背景

当前 Vibe Kanban 的左侧栏（AppBar）是一个图标导航栏，提供项目切换、工作区入口、导出等功能。用户在操作 Kanban 看板时，如果需要 AI 辅助（如批量创建 Issue、分析项目进度、智能排期等），必须手动创建 Workspace 会话，离开看板视图进入聊天界面。这种模式打断了用户的工作流，增加了操作成本。

### 1.2 目标

将 Kanban 项目页面的左侧区域改造为**常驻助手 Agent 面板**，提供一个始终可见、可随时对话的 AI 助手。该助手深度集成 Kanban 业务上下文，能够：

- 理解当前看板的项目、Issue、列状态等上下文
- 通过自然语言执行 Kanban 操作（创建、移动、筛选、批量操作等）
- 主动提供洞察和建议（进度风险、负载不均、阻塞项提醒等）
- 与用户协作完成复杂的项目管理任务

### 1.3 核心设计原则

1. **常驻可见**：助手面板在看板页面始终可见，不遮挡主要内容
2. **上下文感知**：助手自动感知当前项目、选中 Issue、筛选条件等上下文
3. **双向操作**：用户在 Kanban 上的操作实时同步给助手，助手也可操作 Kanban
4. **渐进式交互**：支持从简单的快捷指令到复杂的多轮对话
5. **非侵入式**：助手建议不打断用户流程，以温和的方式呈现

## 2. 用户场景

### 2.1 场景一：快速创建 Issue

> 用户正在规划 Sprint，需要批量创建多个 Issue。

- 用户在助手输入框输入："帮我创建 5 个 Issue：用户登录、注册、找回密码、OAuth 集成、权限管理，都放在 Todo 列，优先级 P1"
- 助手解析意图，在 Todo 列依次创建 5 个 Issue，并回报结果
- 用户可在看板上立即看到新创建的卡片

### 2.2 场景二：智能筛选与查找

> 用户想快速找到特定条件下的 Issue。

- 用户输入："显示所有分配给张三的 P0 Issue"
- 助手自动设置看板筛选条件：Assignee = 张三，Priority = P0
- 同时助手以文字形式列出筛选结果的摘要

### 2.3 场景三：批量操作

> Sprint 结束时，用户需要批量移动 Issue。

- 用户输入："把 Todo 列中所有标签为 bug 的 Issue 移到 Done 列"
- 助手展示匹配的 Issue 列表，请求确认
- 用户确认后，助手执行批量移动，看板实时更新

### 2.4 场景四：进度分析与建议

> 用户想知道项目当前的健康状况。

- 用户输入："分析一下当前 Sprint 的进度"
- 助手分析各列 Issue 分布、临近截止日期的项、阻塞项等
- 输出结构化的分析报告，标记风险项

### 2.5 场景五：上下文感知的智能建议

> 用户选中一个 Issue 查看详情时。

- 助手自动感知当前选中的 Issue
- 在面板中显示相关上下文：关联的 PR、子任务进度、评论摘要
- 主动建议："这个 Issue 有 3 个子任务全部完成，是否将其移到 Review 列？"

### 2.6 场景六：自然语言看板导航

> 用户想快速导航到特定视图。

- 用户输入："切换到列表视图" / "只看我的 Issue" / "按优先级排序"
- 助手执行对应的视图切换和排序操作

## 3. 功能需求

### 3.1 助手面板 UI

#### FR-1.1 面板布局

- 助手面板位于看板页面左侧，替代或融合现有 AppBar
- 支持**折叠/展开**：折叠时显示为窄图标栏（类似现有 AppBar），展开时显示完整面板（宽度约 320px）
- 展开状态可**钉住**（pin），也可设置为鼠标悬停时临时展开
- 面板与看板内容区之间有可拖拽的分隔线（resizable）

#### FR-1.2 面板内容结构

展开后的面板从上到下包含：

```
+----------------------------------+
|  [助手头像/图标]  Kanban 助手     |  ← 标题栏
|  [当前项目名称]                   |  ← 上下文指示
+----------------------------------+
|                                  |
|  对话历史区域                     |  ← 消息列表
|  （虚拟滚动，支持大量消息）        |
|                                  |
|                                  |
+----------------------------------+
|  [快捷操作按钮组]                 |  ← 建议指令
|  [输入框................] [发送]  |  ← 消息输入
+----------------------------------+
```

#### FR-1.3 快捷操作栏

输入框上方提供常用操作的快捷按钮，根据当前上下文动态变化：

| 上下文 | 快捷操作 |
|--------|----------|
| 默认 | 创建 Issue、查看进度、筛选 Issues |
| 选中 Issue | 修改状态、分配成员、添加子任务、查看详情 |
| 多选 Issue | 批量移动、批量分配、批量修改优先级 |
| 筛选激活 | 清除筛选、保存为视图 |

### 3.2 对话交互

#### FR-2.1 消息类型

助手支持以下消息类型：

| 类型 | 描述 | 示例 |
|------|------|------|
| 文本消息 | 普通对话文本，支持 Markdown | 分析报告、操作反馈 |
| 操作确认卡片 | 执行操作前的确认，含预览和确认/取消按钮 | 批量操作预览 |
| Issue 卡片 | 内联展示 Issue 摘要，可点击跳转 | 搜索结果列表 |
| 进度图表 | 嵌入简单的数据可视化 | 燃尽图、分布饼图 |
| 操作结果 | 操作完成后的结果摘要 | "已创建 5 个 Issue" |

#### FR-2.2 上下文传递

助手自动感知以下上下文并随每次请求传递给后端：

- 当前项目 ID、名称
- 当前看板视图状态（筛选条件、排序方式、视图模式）
- 当前选中/打开的 Issue ID
- 多选状态下的 Issue ID 列表
- 用户最近的看板操作历史（最近 10 条）

#### FR-2.3 意图识别与执行

助手需要识别以下意图类别：

| 意图类别 | 示例表述 | 对应操作 |
|----------|----------|----------|
| 创建 Issue | "创建..."、"新建..." | 调用 Issue 创建 API |
| 查询 Issue | "显示..."、"查找..."、"有哪些..." | 设置筛选 / 返回列表 |
| 修改 Issue | "把...改为..."、"设置...为..." | 调用 Issue 更新 API |
| 移动 Issue | "把...移到..." | 调用 Issue 状态变更 API |
| 删除 Issue | "删除..."、"移除..." | 调用 Issue 删除 API |
| 视图操作 | "切换视图"、"按...排序" | 修改看板视图状态 |
| 分析报告 | "分析..."、"总结..."、"报告..." | 生成分析内容 |
| 批量操作 | 涉及多个 Issue 的操作 | 批量 API 调用 |

### 3.3 操作确认机制

#### FR-3.1 确认策略分级

| 风险等级 | 操作类型 | 确认策略 |
|----------|----------|----------|
| 低风险 | 查询、筛选、视图切换 | 自动执行，无需确认 |
| 中风险 | 创建单个 Issue、修改单个 Issue 属性 | 展示预览后自动执行，支持撤销 |
| 高风险 | 批量操作、删除 Issue | 必须用户确认后执行 |

#### FR-3.2 撤销机制

- 中风险及以上操作执行后，提供"撤销"按钮，有效期为操作后 30 秒
- 撤销通过调用反向 API 实现（如移动回原列、恢复删除的 Issue）

### 3.4 主动建议

#### FR-4.1 触发条件

助手在以下情况主动推送建议：

- 用户打开看板页面时（欢迎消息 + 项目概览）
- 用户长时间未操作某个 Issue 时（提醒关注）
- Issue 在某一列停留超过设定阈值时（流程卡顿提醒）
- 检测到 Issue 之间存在依赖异常时（如子任务完成但父任务未移动）
- 接近截止日期时（到期提醒）

#### FR-4.2 呈现方式

- 主动建议以非打断方式呈现：在助手面板中以新消息形式出现，带有视觉提示（如小圆点）
- 用户可以关闭/忽略建议
- 用户可配置主动建议的开关和频率

### 3.5 多模态交互（后期规划）

- **语音输入**：支持语音转文字输入指令
- **拖拽交互**：从助手面板拖拽生成的 Issue 卡片到看板列
- **@提及**：在看板评论中 @助手 可触发助手分析

## 4. UI/UX 设计需求

### 4.1 布局方案

采用**方案 B：左侧可折叠面板**（推荐）

```
Desktop Layout (展开状态):
+------------------+-----------------------------------+
|                  |         Navbar                     |
|   Kanban 助手    +-----------------------------------+
|   (320px)       |                                   |
|                  |        Kanban 看板区域             |
|  - 对话历史      |                                   |
|  - 快捷操作      |   [Todo] [In Progress] [Done]     |
|  - 输入框        |                                   |
|                  |                                   |
+------------------+-----------------------------------+

Desktop Layout (折叠状态):
+------+---------------------------------------------------+
|      |         Navbar                                     |
| AppBar+---------------------------------------------------+
| 图标  |                                                   |
| 导航  |        Kanban 看板区域                             |
|      |                                                   |
|      |   [Todo] [In Progress] [Done]                     |
|      |                                                   |
+------+---------------------------------------------------+
```

折叠状态下的 AppBar 保留原有核心功能：

- 助手图标（点击展开）
- 项目列表
- 工作区入口
- 通知
- 设置

### 4.2 响应式设计

- **桌面端（>=1024px）**：左侧面板可折叠/展开，默认展开
- **平板端（768px - 1023px）**：默认折叠，手动展开时为覆盖模式（overlay）
- **移动端（<768px）**：助手入口集成到底部导航栏，以底部抽屉形式展开

### 4.3 主题与样式

- 遵循项目现有设计系统（Tailwind + `@vibe/ui` 组件库）
- 支持亮色/暗色主题
- 助手消息气泡与用户消息气泡有明确的视觉区分
- 操作确认卡片使用项目现有的 Card 组件风格

### 5.2 后端架构

#### 5.2.1 Agent 服务

在 `crates/services/` 下新增 `kanban-agent` 模块：

```
crates/services/kanban-agent/
├── mod.rs
├── agent.rs              # Agent 核心逻辑
├── intents.rs            # 意图识别
├── actions.rs            # 操作执行
├── context.rs            # 上下文收集与传递
├── suggestions.rs        # 主动建议生成
└── prompts/
    ├── mod.rs
    ├── system.rs         # 系统提示词
    └── templates.rs      # 各类操作的提示词模板
```

#### 5.2.2 API 端点

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | `/api/projects/:id/agent/chat` | 发送消息给助手，返回 SSE 流式响应 |
| GET | `/api/projects/:id/agent/context` | 获取当前上下文快照 |
| POST | `/api/projects/:id/agent/suggestions` | 获取主动建议 |
| PUT | `/api/projects/:id/agent/preferences` | 更新助手偏好设置 |

### 5.3 通信协议

- 对话通信使用 **Server-Sent Events (SSE)** 实现流式响应
- 看板操作实时同步使用现有 **WebSocket** 通道（与现有 Workspace 机制复用或独立通道）
- 助手操作看板的结果通过现有看板事件系统同步到 UI

### 5.4 意图处理流程

```
用户输入 → [前端预处理: 提取实体] → POST /agent/chat
                                            ↓
                              [后端: LLM 意图识别 + 参数提取]
                                            ↓
                        ┌───────────────────┴───────────────────┐
                        ↓                                       ↓
                  查询类操作                               写入类操作
                        ↓                                       ↓
              [查询数据库/筛选]                        [操作确认策略判断]
                        ↓                                       ↓
              [格式化返回结果]                    ┌─────┴─────┐
                                                 ↓             ↓
                                            需确认        无需确认
                                                 ↓             ↓
                                        [返回确认卡片]   [执行操作]
                                                 ↓             ↓
                                        [用户确认后执行]  [返回结果]
```

### 5.5 与现有系统集成

#### 5.5.1 与 Workspace 系统的关系

- Kanban 常驻助手是**独立的 Agent 实例**，不同于现有的 Workspace 会话
- 常驻助手专注于 Kanban 业务操作，Workspace 专注于代码开发任务
- 常驻助手可**创建 Workspace**：当用户需求超出 Kanban 操作范围时（如"为这个 Issue 创建开发分支"），助手可引导用户创建 Workspace
- 在路由 `/projects/$projectId/issues/$issueId/workspaces/$workspaceId` 下，右侧已有 Workspace 面板，左侧为看板。常驻助手与 Workspace 可同时存在

#### 5.5.2 与看板状态管理集成

- 助手操作看板时，通过现有的 `ProjectMutationsRegistration` 机制触发变更
- 看板筛选、排序状态的变更支持双向同步（用户在 UI 操作 ↔ 助手操作）
- 使用现有 React Query cache 机制，助手操作后自动 invalidate 相关查询

#### 5.5.3 路由设计

在现有路由基础上，助手面板作为看板页面的持久化 UI 元素，不需要新增独立路由：

- `/_app/projects/$projectId` — 看板 + 助手面板
- `/_app/projects/$projectId/issues/$issueId` — 看板 + 助手面板 + Issue 详情
- `/_app/projects/$projectId/issues/$issueId/workspaces/$workspaceId` — 看板 + 助手面板 + Workspace

助手面板的展开/折叠状态存储在 `localStorage` 中，不体现在 URL 上。

## 6. 提示词设计

### 6.1 系统提示词框架

```
你是一个 Kanban 项目管理助手。你的职责是帮助用户管理当前项目中的 Issue。

## 当前上下文
- 项目名称：{project_name}
- 项目列：{columns}
- 当前视图：{view_state}
- 选中 Issue：{selected_issue}

## 可用操作
1. 查询 Issues：支持按状态、优先级、标签、负责人等筛选
2. 创建 Issue：需要标题、状态列，可选优先级、标签、负责人、描述
3. 修改 Issue：可修改标题、描述、优先级、标签、负责人、截止日期
4. 移动 Issue：改变 Issue 所在列
5. 删除 Issue：永久删除（需确认）
6. 视图控制：切换看板视图、设置筛选条件、排序方式

## 行为准则
- 查询和分析类操作直接执行
- 修改和移动单个 Issue 展示预览后执行
- 批量操作和删除必须获得用户确认
- 回复简洁，操作结果用一两句话总结
- 如果用户请求超出 Kanban 操作范围，建议创建 Workspace 处理
```

## 7. 非功能性需求

### 7.1 性能

- 助手面板首次渲染时间 < 200ms
- 对话消息发送到首个 token 返回（TTFT）< 1.5s
- 对话历史虚拟滚动支持 1000+ 条消息不掉帧
- 助手操作看板到 UI 更新延迟 < 500ms

### 7.2 可靠性

- 网络断开时助手面板显示离线状态，不可发送消息
- 操作执行失败时有明确的错误提示和重试机制
- 撤销操作在 30 秒内保证有效

### 7.3 安全性

- 助手操作权限与用户权限一致（通过现有认证机制）
- 删除、批量操作等高风险操作需要用户确认
- 助手不可执行超出当前用户权限的操作
- 用户可随时清除助手对话历史

### 7.4 可配置性

- 用户可配置助手的主动建议开关
- 用户可配置操作确认级别（宽松/标准/严格）
- 用户可配置面板默认展开状态
- 管理员可为组织配置助手的全局开关

### 7.5 国际化

- 助手界面支持中英文切换
- 助手回复语言跟随用户语言偏好设置
- Issue 相关术语使用项目配置的术语表

## 8. 实现阶段规划

### Phase 1：基础框架（MVP）

### Phase 3：智能增强

- 主动建议与提醒
- 进度分析与报告

- 拖拽交互（从助手拖拽到看板）
- 语音输入
- @提及集成
- 用户偏好学习
- 操作模板（可保存的常用操作序列）

## 9. 风险与待定问题

| 风险/问题 | 影响 | 缓解措施 |
|-----------|------|----------|
| LLM 响应延迟影响体验 | 用户等待时间过长 | 前端预处理简单意图；流式响应；乐观更新 |
| 意图识别准确率不足 | 用户失望、操作错误 | 操作确认机制；支持手动纠正；持续优化提示词 |
| 与现有 Workspace 系统定位重叠 | 用户困惑 | 明确职责边界；交互设计中引导区分 |
| 移动端屏幕空间不足 | 体验下降 | 底部抽屉设计；精简功能；语音输入 |
| 后端资源消耗 | 增加服务器负载 | 复用 LLM 调用的缓存；限制主动建议频率 |

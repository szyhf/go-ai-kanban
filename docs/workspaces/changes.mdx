变更面板让你可以审查工作空间中的所有代码修改，并向 Agent 提供反馈。

## 为什么要审查变更？

在提交或创建 PR 之前，你应该始终审查 Agent 所做的更改：

- **验证正确性** - 代码是否按你的要求执行？
- **检查问题** - 是否有 Bug、安全问题或风格违规？
- **理解方法** - 了解 Agent 做了什么，以便向审查者解释
- **提供反馈** - 在提交前让 Agent 修复问题

<Warning>
**不要盲目信任 Agent 的输出。** 在合并前始终审查变更。Agent 可能会犯错、引入 Bug 或误解需求。
</Warning>

## 打开变更面板

- 点击导航栏中的**变更**切换按钮（<Icon icon="code-compare" />）
- 点击上下文栏中的变更图标
- 使用命令栏：`Cmd/Ctrl + K` → "切换变更面板"

## 文件树

变更面板显示层级文件树：

- **文件夹**：展开/折叠以导航
- **文件**：点击查看 Diff
- **搜索**：按名称筛选文件
- **全部展开/折叠**：快速导航按钮

## Diff 查看器

通过语法高亮查看代码变更：

| 功能 | 描述 |
|------|------|
| **新增** | 绿色高亮显示新增行 |
| **删除** | 红色高亮显示删除行 |
| **上下文** | 周围未更改的行作为参考 |
| **行号** | 原始和新行号 |

## Diff 视图模式

在两种显示模式之间切换：

| 模式 | 描述 |
|------|------|
| **统一视图** | 内联视图，变更交错显示 |
| **并排视图** | 原始和修改内容并排显示 |

使用导航栏中的 Diff 视图切换按钮（变更面板打开时）或命令栏切换模式：`Cmd/Ctrl + K` → "切换 Diff 视图模式"。

## Diff 选项

自定义 Diff 显示：

| 选项 | 描述 |
|------|------|
| **自动换行** | 启用/禁用长行换行 |
| **忽略空白** | 显示/隐藏仅空白字符的变更 |
| **全部展开** | 展开所有折叠的 Diff 部分 |
| **全部折叠** | 折叠所有 Diff 部分 |

通过命令栏的 Diff 选项页面访问这些功能。

## 通过注释提供反馈

<Frame>
<img style={{maxHeight: "350px"}} src="/images/workspaces-inline-comments.png" alt="变更面板显示代码上的行内注释和添加审查注释按钮" />
</Frame>

直接在代码变更上添加注释，向 Agent 提供反馈。

### 添加注释

1. 将鼠标悬停在 Diff 中的某一行上
2. 点击出现的注释图标
3. 编写你的反馈
4. 提交注释

### 注释用途

- **请求修改**：让 Agent 修改特定代码
- **提问**：获取关于实现选择的解释
- **提供上下文**：分享额外的需求或约束
- **认可代码**：标记看起来没问题的代码段

### Agent 对注释的响应

<Frame>
<img style={{maxHeight: "300px"}} src="/images/workspaces-review-comments-response.png" alt="聊天显示 Agent 通过恢复文件来响应审查注释" />
</Frame>

当你发送带有审查注释的消息时，Agent 会看到你的反馈并据此行动。在此示例中，Agent 在用户请求撤销变更后恢复了文件。

<Info>
注释在后续消息中对 Agent 可见，帮助指导进一步的开发。
</Info>

## 审查工作流

按照此工作流有效审查和优化 Agent 的变更：

<Steps>
<Step title="等待 Agent 完成">
让 Agent 完成其工作。侧边栏中的状态将从"运行中"变为"空闲"。
</Step>

<Step title="打开变更面板">
点击导航栏中的变更图标或使用 `Cmd/Ctrl + K` → "切换变更面板"。
</Step>

<Step title="审查每个文件">
在文件树中点击每个修改过的文件。注意查看：
- **逻辑错误** - 代码是否按你的意图执行？
- **遗漏部分** - 是否有未处理的边界情况？
- **代码质量** - 代码是否可读且可维护？
- **安全问题** - 是否有明显的漏洞？
</Step>

<Step title="对问题添加注释">
对于发现的任何问题，将鼠标悬停在该行上并点击注释图标。编写具体的反馈：

**好的注释：** "这个 API 端点应该在查询数据库之前验证用户 ID，以防止未授权访问。"

**不好的注释：** "这不对，修一下。"
</Step>

<Step title="向 Agent 发送反馈">
在聊天中输入消息（例如"请处理审查注释"）并发送。Agent 会看到你的行内注释并进行修正。
</Step>

<Step title="再次审查并重复">
Agent 处理完反馈后，审查新的变更。重复直到你满意为止。
</Step>

<Step title="准备好后创建 PR">
变更看起来没问题后，使用 Git 面板或命令栏创建 Pull Request。
</Step>
</Steps>

<Tip>
**注释要具体。** 不要说"这不对"，而是解释哪里不对，最好提出修复建议。你提供的上下文越多，Agent 就能越好地修正问题。
</Tip>

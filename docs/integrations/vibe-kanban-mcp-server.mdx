Vibe Kanban 暴露了一个本地 MCP（模型上下文协议）服务器，允许你从外部 MCP 客户端（如 Claude Desktop、Raycast，甚至在 Vibe Kanban 内部运行的编程智能体）管理组织、项目、议题、工作区和仓库。

<Note>
本页面介绍如何将**外部 MCP 客户端**连接到 Vibe Kanban 的 MCP 服务器。如需在 Vibe Kanban **内部**为编程智能体配置 MCP 服务器，请参阅 [MCP 服务器配置](/integrations/mcp-server-configuration)指南。
</Note>

<Info>
Vibe Kanban 的 MCP 服务器**仅限本地访问**——它运行在你的计算机上，只能被本地安装的应用程序访问，无法通过公开可访问的 URL 进行访问。
</Info>

## 设置 MCP 集成

### 方式一：使用 Web 界面

如果你要将 Vibe Kanban MCP 服务器添加到 Vibe Kanban **内部**的任何[支持的编程智能体](/supported-coding-agents)，可以使用此方式。

1. 在 Vibe Kanban 设置中，导航到"MCP Servers"页面
2. 在"Popular servers"部分，点击 Vibe Kanban 卡片
3. 点击 `Save Settings` 按钮

<Frame>
<img src="/images/vk-mcp-server-config.png" alt="MCP 服务器配置页面，展示如何添加 Vibe Kanban MCP 服务器" />
</Frame>

### 方式二：手动配置

你可以手动将 MCP 服务器添加到编程智能体的配置中。具体语法取决于你使用的编程智能体或 MCP 客户端。

将以下配置添加到你的智能体的 MCP 服务器配置中：

```json
{
  "mcpServers": {
    "vibe_kanban": {
      "command": "npx",
      "args": ["-y", "vibe-kanban@latest", "--mcp"]
    }
  }
}
```

`--mcp` 启动本地 MCP stdio 服务器。`--mcp` 之后的任何额外参数将传递给 `vibe-kanban-mcp` 二进制文件。

## 可用的 MCP 工具

Vibe Kanban MCP 服务器提供了用于管理组织、项目、议题、工作区和任务执行的工具。

<Note>
许多工具接受可选的 `project_id` 或 `organization_id` 参数。当在与远程项目关联的工作区内运行时，这些参数可以从上下文中自动推断，因此可以省略。例外是 `list_projects`，它始终需要显式的 `organization_id`。
</Note>

### 上下文

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `get_context` | 获取当前工作区上下文（仅在活跃的工作区会话中可用） | 无 | 无 | 项目、议题和工作区元数据 |

### 组织操作

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_organizations` | 列出所有可用的组织 | 无 | 无 | 包含 ID、名称和 slug 的组织列表 |
| `list_org_members` | 列出组织的成员 | 无 | `organization_id` | 包含用户 ID、角色和个人资料的成员列表 |

### 项目操作

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_projects` | 列出组织中的项目 | `organization_id` | 无 | 包含 ID 和名称的项目列表 |

### 议题管理

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_issues` | 列出项目中的议题 | 无 | `project_id`<br/>`status`<br/>`priority`<br/>`search`<br/>`simple_id`<br/>`parent_issue_id`<br/>`assignee_user_id`<br/>`tag_id`<br/>`tag_name`<br/>`limit`<br/>`offset` | 分页的议题列表，包含 PR 信息 |
| `create_issue` | 创建新议题 | `title` | `project_id`<br/>`description`<br/>`priority`<br/>`parent_issue_id` | 创建的议题 ID |
| `get_issue` | 获取议题详细信息 | `issue_id` | 无 | 完整的议题详情，包含标签、关系、子议题和 PR |
| `update_issue` | 更新现有议题 | `issue_id` | `title`<br/>`description`<br/>`status`<br/>`priority`<br/>`parent_issue_id` | 更新后的议题详情 |
| `delete_issue` | 删除议题 | `issue_id` | 无 | 删除确认 |
| `list_issue_priorities` | 列出允许的优先级值 | 无 | 无 | 优先级列表：urgent、high、medium、low |

<Tip>
对于 `update_issue`，`parent_issue_id` 字段支持三种状态：完全省略以保持父议题不变，传入 `null` 以取消议题与父议题的嵌套关系，或传入 UUID 以设置新的父议题。
</Tip>

### 议题分配

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_issue_assignees` | 列出议题的分配人 | `issue_id` | 无 | 包含用户 ID 的分配人列表 |
| `assign_issue` | 将用户分配到议题 | `issue_id`<br/>`user_id` | 无 | 议题分配人 ID |
| `unassign_issue` | 从议题中移除分配人 | `issue_assignee_id` | 无 | 取消分配确认 |

### 议题标签

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_tags` | 列出项目的标签 | 无 | `project_id` | 包含 ID、名称和颜色的标签列表 |
| `list_issue_tags` | 列出附加到议题的标签 | `issue_id` | 无 | 议题-标签关系列表 |
| `add_issue_tag` | 将标签附加到议题 | `issue_id`<br/>`tag_id` | 无 | 议题-标签关系 ID |
| `remove_issue_tag` | 从议题中移除标签 | `issue_tag_id` | 无 | 移除确认 |

### 议题关系

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `create_issue_relationship` | 创建两个议题之间的关系 | `issue_id`<br/>`related_issue_id`<br/>`relationship_type` | 无 | 关系 ID |
| `delete_issue_relationship` | 删除议题之间的关系 | `relationship_id` | 无 | 删除确认 |

支持的关系类型：`blocking`、`related`、`has_duplicate`。

### 仓库管理

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_repos` | 列出所有仓库 | 无 | 无 | 包含 ID 和名称的仓库列表 |
| `get_repo` | 获取仓库详情，包括脚本 | `repo_id` | 无 | 仓库信息，包含设置、清理和开发服务器脚本 |
| `update_setup_script` | 更新仓库的设置脚本 | `repo_id`<br/>`script` | 无 | 更新确认 |
| `update_cleanup_script` | 更新仓库的清理脚本 | `repo_id`<br/>`script` | 无 | 更新确认 |
| `update_dev_server_script` | 更新仓库的开发服务器脚本 | `repo_id`<br/>`script` | 无 | 更新确认 |

### 工作区管理

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `list_workspaces` | 列出本地工作区 | 无 | `archived`<br/>`pinned`<br/>`branch`<br/>`name_search`<br/>`limit`<br/>`offset` | 分页的工作区列表 |
| `update_workspace` | 更新工作区属性 | 无 | `workspace_id`<br/>`archived`<br/>`pinned`<br/>`name` | 更新后的工作区详情 |
| `delete_workspace` | 删除本地工作区 | 无 | `workspace_id`<br/>`delete_remote`<br/>`delete_branches` | 删除确认 |
| `link_workspace_issue` | 将工作区关联到远程议题 | `workspace_id`<br/>`issue_id` | 无 | 关联确认 |

### 工作区会话

| 工具 | 用途 | 必需参数 | 可选参数 | 返回值 |
|------|---------|-------------------|-------------------|---------|
| `start_workspace` | 创建工作区并启动其第一个编程智能体会话 | `name`<br/>`executor`<br/>`repositories` | `prompt`<br/>`variant`<br/>`issue_id` | 工作区 ID |
| `create_session` | 在现有工作区中创建会话 | 无 | `workspace_id`<br/>`executor` | 会话摘要 |
| `list_sessions` | 列出工作区的会话 | 无 | `workspace_id` | 会话列表 |
| `run_session_prompt` | 在现有会话中运行编程智能体提示 | `session_id`<br/>`prompt` | 无 | 执行详情 |
| `get_execution` | 检查执行状态和最终消息 | `execution_id` | 无 | 执行详情 |

`repositories` 参数是一个对象数组，包含：
- `repo_id`：仓库 ID（UUID）
- `branch`：此仓库的分支

当提供 `issue_id` 时，工作区会自动关联到远程议题。如果省略 `prompt`，则使用关联议题的标题和描述作为工作区提示。

### 支持的执行器

使用 `start_workspace` 时，支持以下执行器（不区分大小写，接受连字符或下划线）：

- `claude-code` / `CLAUDE_CODE`
- `amp` / `AMP`
- `gemini` / `GEMINI`
- `codex` / `CODEX`
- `opencode` / `OPENCODE`
- `cursor_agent` / `CURSOR_AGENT`
- `qwen-code` / `QWEN_CODE`
- `copilot` / `COPILOT`
- `droid` / `DROID`

## 使用 MCP 服务器

配置好 MCP 服务器后，你可以利用它来简化项目规划和执行工作流：

1. **规划工作**：向你的 MCP 客户端描述一个大型功能或项目
2. **请求创建议题**：在描述的最后，添加"然后将此计划转为议题"
3. **自动生成议题**：你的 MCP 客户端将使用 Vibe Kanban MCP 服务器自动在项目中创建结构化的议题
4. **启动工作区**：使用 `start_workspace` 以编程方式开始使用特定编程智能体处理议题

## 使用示例

### 规划和创建议题

```
I need to build a user authentication system with the following features:
- User registration with email validation
- Login/logout functionality
- Password reset capability
- Session management
- Protected routes

Then turn this plan into issues.
```

你的 MCP 客户端将使用 `create_issue` 工具将其分解为单独的议题，并自动添加到你的 Vibe Kanban 项目中。

### 启动工作区会话

创建议题后，你可以以编程方式开始处理它们：

```
Start working on the user registration issue using Claude Code on the main branch.
```

你的 MCP 客户端将使用 `start_workspace` 工具，参数如下：
```json
{
  "name": "User registration with email validation",
  "executor": "claude-code",
  "repositories": [
    {
      "repo_id": "987fcdeb-51a2-3d4e-b678-426614174001",
      "branch": "main"
    }
  ],
  "issue_id": "123e4567-e89b-12d3-a456-426614174000"
}
```

这将创建一个新的工作区，将其关联到议题，生成功能分支，并在隔离环境中启动编程智能体。

### 完整工作流示例

```
1. List organisations to find the organisation ID
2. List projects in the organisation to find the project ID
3. List issues in the project filtered by status
4. Create a new issue for "Add user profile page"
5. Assign a team member to the issue
6. Start a workspace session for the issue using Amp on the develop branch
```

每一步都使用相应的 MCP 工具（`list_organizations`、`list_projects`、`list_issues`、`create_issue`、`assign_issue`、`start_workspace`）来管理从规划到执行的完整工作流。

### 内部编程智能体（在 Vibe Kanban 内）

一种强大的工作流是在 Vibe Kanban 内使用同时连接到 Vibe Kanban MCP 服务器的编程智能体：

1. **创建规划议题**：创建一个议题，并配置一个带有规划提示的自定义智能体配置文件。有关创建自定义配置文件的详情，请参阅[智能体配置](/settings/agent-configurations)。
2. **探索和规划**：编程智能体探索代码库并制定全面的计划
3. **生成议题**：要求编程智能体"为此计划创建一系列单独的议题"
4. **自动填充**：智能体使用 MCP 服务器直接在 Vibe Kanban 界面中填充单独的议题

这创建了一个无缝的工作流，高级规划会自动在项目看板中生成可操作的议题。

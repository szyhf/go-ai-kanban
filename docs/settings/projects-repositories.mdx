## 项目

<Frame>
<img src="/images/settings-projects.png" alt="Projects tab showing project selection and project-specific settings" />
</Frame>

项目标签页允许你配置特定项目的设置。

### 访问项目设置

1. 从工作区导航栏打开 **Settings**
2. 选择 **Projects** 标签页
3. 从下拉菜单中选择一个项目以查看和修改其设置

<Tip>
在适用的情况下，项目设置会覆盖全局设置。
</Tip>

## 仓库

<Frame>
<img src="/images/settings-repositories.png" alt="Repositories tab showing repository selection, general settings, and scripts configuration" />
</Frame>

仓库标签页允许你配置在工作区中使用仓库时运行的脚本。

### 访问仓库设置

1. 从工作区导航栏打开 **Settings**
2. 选择 **Repositories** 标签页
3. 从下拉菜单中选择一个仓库以查看和修改其设置

### 通用设置

配置基本仓库信息：

- **显示名称** - 此仓库的友好名称
- **仓库路径** - 仓库的本地路径

## 脚本与配置

为此仓库配置开发服务器、初始化和清理脚本。这些脚本在任何工作区中使用该仓库时都会运行，确保一致的开发环境。

### 开发服务器脚本

启动开发服务器的命令。这将启用工作区中内置的预览浏览器，让你在更改代码时能看到应用程序的运行状态。

**常见示例：**

| 框架 | 命令 |
|-----------|---------|
| Vite | `npm run dev` |
| Next.js | `npm run dev` |
| Create React App | `npm start` |
| Django | `python manage.py runserver` |
| Rails | `rails server` |

<Tip>
开发服务器必须将其 URL（如 `http://localhost:3000`）输出到 stdout，Vibe Kanban 才能检测并在预览面板中显示它。
</Tip>

### 初始化脚本

在编程 Agent **开始工作之前**运行的命令。用于准备开发环境。

**为什么要使用初始化脚本？**

- **安装依赖** - 确保 Agent 修改代码之前所有包已安装
- **构建前置条件** - 编译共享库或生成 Agent 需要的文件
- **环境准备** - 设置数据库、拉取 Docker 镜像或配置服务

**示例：**

```bash
# Node.js 项目
npm install

# Python 项目
pip install -r requirements.txt

# 多个命令
npm install && npm run build:deps

# Go 项目
go mod download
```

<Info>
初始化脚本在仓库根目录中运行。它们在工作区启动时执行一次，而不是每条 Agent 消息时执行。
</Info>

### 清理脚本

**当工作区关闭时**运行的命令。用于清理资源和停止后台进程。

**为什么要使用清理脚本？**

- **停止服务** - 终止可能与其他工作区冲突的后台进程
- **释放资源** - 释放数据库连接、Docker 容器或其他资源
- **清理临时文件** - 移除构建产物或缓存文件
- **格式化代码** - 在 Agent 更改后运行格式化工具确保代码风格一致

**示例：**

| 用例 | 命令 |
|----------|------|
| 停止 Docker 容器 | `docker compose down` |
| 终止后台进程 | `pkill -f "node server.js"` |
| 清理构建产物 | `rm -rf dist/ .cache/` |
| 停止 PostgreSQL | `pg_ctl stop -D /usr/local/var/postgres` |
| 终止端口上的进程 | `lsof -ti:3000 \| xargs kill -9 2>/dev/null` |

**代码格式化示例：**

| 语言/工具 | 命令 |
|---------------|---------|
| JavaScript/TypeScript (Prettier) | `npx prettier --write .` |
| JavaScript/TypeScript (ESLint) | `npx eslint --fix .` |
| Python (Black) | `black .` |
| Python (Ruff) | `ruff check --fix .` |
| Go | `go fmt ./...` |

**组合多个命令：**

```bash
# 使用 && 链接命令
docker compose down && rm -rf tmp/

# Agent 更改后格式化代码
npx prettier --write . && npx eslint --fix .

# Go 格式化和 lint
gofmt -w . && go vet ./...

# 使用 || true 忽略失败
pkill -f "node server.js" || true
rm -rf .cache/ || true
```

<Warning>
清理脚本应该是幂等的——即使资源不存在也能安全运行。使用 `|| true` 来防止在无需清理时出现失败。
</Warning>

## 最佳实践

<AccordionGroup>
<Accordion title="保持脚本快速">
长时间运行的初始化脚本会延迟工作区启动。在初始化中安装依赖，但避免不必要的冗长构建过程。
</Accordion>

<Accordion title="使用相对路径">
脚本从仓库根目录运行。使用相对路径或环境变量，而不是硬编码的绝对路径。
</Accordion>

<Accordion title="优雅地处理错误">
为可能失败但不应阻塞工作区的命令添加 `|| true`：
```bash
npm install || true
```
</Accordion>

<Accordion title="在本地测试脚本">
在 Vibe Kanban 中配置脚本之前，先在终端中手动运行以确保它们正常工作。
</Accordion>
</AccordionGroup>

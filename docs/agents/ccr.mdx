CCR (Claude Code Router) 可以将编码提示路由到不同的 LLM 提供商和模型，并为特定任务选择专用模型，例如长上下文、后台任务或图像理解。

<Warning>
CCR 与 Claude Code 或 Anthropic 没有任何关联、背书或连接。它是一个第三方工具。
</Warning>

## 安装
CCR 可通过 `npx` 使用——无需单独安装。

```bash
npx -y @musistudio/claude-code-router ui
```

这将启动 CCR 本地 UI，你可以在其中配置提供商和模型。

## 身份验证
在 Vibe Kanban 之外完成 CCR 的身份验证和配置。请按照 CCR GitHub 仓库中的说明操作：

- GitHub: https://github.com/musistudio/claude-code-router

你需要在 CCR UI 中添加提供商、设置 API 密钥并注册模型名称，或者通过 CCR 的 JSON 配置完成（有关 schema 和文件位置请参阅 CCR 仓库）。

## 配置 CCR（提供商和模型）

可以通过 UI 或 JSON 配置来配置 CCR。

在 CCR UI 中（`npx -y @musistudio/claude-code-router ui`）：

1) 添加提供商
- 选择一个提供商（例如 `openrouter`、`deepseek` 等）。
- 输入该提供商所需的 API 密钥和设置。

2) 添加模型
- 为每个提供商注册模型标识符（例如 `moonshotai/kimi-k2-0905`、`deepseek-chat`）。
- CCR 支持为特定场景配置不同的模型：
  - `default`：通用编码
  - `background`：轻量级/后台操作
  - `think`：支持"思考"模式的模型
  - `longContext`：超长输入/文件
  - `webSearch`：支持网络/工具使用的模型
  - `image`：具备视觉能力的模型

注意：并非所有模型都支持网络搜索、思考或图像功能。请在 CCR UI 中选择相应的模型。

### 通过 JSON 配置（可选）
CCR 也可以通过其 JSON 配置文件进行配置。有关确切的 schema、键名和文件位置，请参阅 CCR GitHub 文档。定义提供商（包含 API 密钥）并将模型场景（`default`、`background`、`think`、`longContext`、`webSearch`、`image`）映射到特定的提供商/模型对。

## 配置 Vibe Kanban

Vibe Kanban 不附带 CCR 的默认配置。你需要在现有的 Claude Code agent 上添加配置：

1) 打开"编程 Agent 配置"页面。
2) 为 Claude Code agent 添加新配置（或编辑现有配置）。
3) 启用 `claude_code_router` 复选框。
4) 可选择设置模型字符串以指定特定的 CCR 提供商/模型。

有关管理 agent 配置的更多信息，请参阅 [Agent 配置与变体](/settings/agent-configurations) 指南。

模型字符串格式：`<provider>,<model-name>`

示例：
```text
openrouter,moonshotai/kimi-k2-0905
deepseek,deepseek-chat
```

提示：
- 如果你想在不同模型之间方便地切换，可以创建多个配置。
- 如果希望 CCR 根据你的 CCR UI 配置（例如 `default`/`longContext` 等映射）自行路由，请将模型字符串留空。

## 在 Vibe Kanban 中使用 CCR

创建任务尝试时，选择编码 agent 和配置：选择 Claude Code agent，然后选择一个已启用 CCR 的配置。

## 故障排除

- 身份验证错误：在 CCR 中验证你的 API 密钥/提供商设置（通过 UI 或 JSON 配置）。
- 找不到模型：确认所选提供商的模型标识符是否正确。
- 功能缺失（webSearch/think/image）：切换到支持该功能的模型并更新 CCR 映射（通过 UI 或 JSON 配置）。

Vibe Kanban 通过简化规划和审查流程，帮助你在并行运行多个编码代理时保持井然有序。

## 1. 启动 Vibe Kanban

启动 Vibe Kanban 客户端并在浏览器中打开界面：

```bash
npx vibe-kanban
```

## 2. 确认偏好设置

首次运行 Vibe Kanban 时，你需要设置以下偏好：

- 编码代理
- IDE
- 通知偏好

<Info>
这些偏好设置随时可以在设置对话框中修改
</Info>

<Frame>
  <img src="/images/onboarding-basic-setup.png" alt="Placeholder image for preferences setup: coding agent, IDE, and sound notifications." />
</Frame>

## 3. 登录 Vibe Kanban

你可以使用 GitHub 或 Google 账号登录。

<Frame>
  <img src="/images/onboarding-sign-in.png" alt="Vibe Kanban onboarding screen showing Sign in to continue with GitHub and Google buttons" />
</Frame>

<Info>
如果你想暂时跳过登录，点击 **更多选项** → **我了解，继续不登录**。你仍然可以创建工作区，但看板、问题和团队功能将不可用。
</Info>

## 4. 导看板页面

登录后，我们会自动为你创建一个个人组织和初始项目，并直接导航到那里。

<Frame>
  <img src="/images/onboarding-projects.png" alt="The projects page" />
</Frame>

**看板导航说明：**

1. 应用栏，用于在项目之间导航、访问工作区页面（稍后会介绍）和用户设置
2. 问题以卡片形式显示在看板上
3. "新建问题"按钮，用于创建问题
4. 右侧面板，显示当前选中或草稿问题的详细信息

## 5. 创建问题

**问题** 是 Vibe Kanban 的核心概念，代表一个 bug、功能或需要完成的工作。问题至少包含标题和描述，但你还可以添加优先级、标签，甚至通过父子关系将问题关联起来。

<Frame>
  <img src="/images/onboarding-create-issue.png" alt="Create issue" />
</Frame>

填写详细信息后，点击"创建问题"。

## 6. 创建工作区

**工作区** 是 Vibe Kanban 的另一个核心概念，代表编码代理处理问题的空间。创建工作区时，Vibe Kanban 会自动为你选择的仓库创建 git worktree，并启动编码代理。

<Frame>
  <img src="/images/onboarding-create-workspace.png" alt="The create workspace button" />
</Frame>

要创建工作区，请确保你创建的问题处于选中状态，然后点击工作区窗口中的"创建"按钮。

<Frame>
  <img src="/images/onboarding-workspaces-repo.png" alt="Workspaces repos" />
</Frame>

创建工作区时，你需要指定要处理的仓库，以及这些仓库中作为 git worktree 基础的分支。

<Frame>
  <img src="/images/onboarding-workspaces-prompt.png" alt="Workspaces prompt" />
</Frame>

你还需要指定所需的编码代理配置（例如模型、投入程度、计划模式）。

<Frame>
  <img src="/images/onboarding-workspaces-logs.png" alt="Workspaces logs" />
</Frame>

创建完成后，编码代理会立即使用给定的提示词开始执行。

<Info>
  你可以将多个工作区连接到一个问题，这在处理大型功能时非常有用，可以让你并行运行多个编码代理。

  工作区不*必须*连接到问题，这对于快速操作（比如询问关于代码库的问题）非常有用。
</Info>

## 7. 审查工作区

到目前为止，我们一直在看板旁边查看工作区。但是，如果我们需要更多空间来审查代码更改或在浏览器中测试它们，可以在 **工作区视图** 中打开工作区。

<Frame>
  <img src="/images/onboarding-workspaces-open.png" alt="Workspaces open" />
</Frame>

要访问工作区视图，点击 **打开工作区** 按钮。

<Frame>
  <img src="/images/onboarding-workspaces-page.png" alt="Workspaces page" />
</Frame>

根据你的需求，你可以使用浮动导航按钮 (3) 查看代码更改或在浏览器中预览网站的更改。

你还可以导航回项目 (1) 或父问题 (2)。

## 8. 合并工作区

当你准备好合并工作区中的更改时，可以创建一个 GitHub Pull Request 或在本地合并工作区分支。

<Frame>
  <img src="/images/onboarding-workspaces-merge.png" alt="Workspaces merge" />
</Frame>

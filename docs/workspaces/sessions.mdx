会话是工作空间中与编码 Agent 的对话线程。每个会话维护自己的对话历史，让你可以处理任务的不同方面或尝试不同的方法。

## 什么是会话？

**会话**是与编码 Agent 的一次对话。把它想象成一个聊天线程：

- **每个会话有自己的对话历史** - 消息、代码变更和上下文
- **会话共享相同的文件** - 一个会话的变更对所有会话可见
- **会话是独立的进程** - 一个在运行时另一个可以是空闲的

<Info>
**关键点：** 会话共享文件但不共享对话上下文。如果会话 1 做了变更，会话 2 可以看到那些文件变更但不知道会话 1 收到了什么指令。
</Info>

## 理解 Token 限制

AI 模型有一个**上下文窗口** - 它们在对话中能"记住"的文本量限制。当你达到这个限制时：

- Agent 可能忘记对话的早期部分
- 回复可能变得不太准确
- 你会看到上下文仪表变为橙色或红色

**解决方案：** 启动新会话。新会话获得一个全新的上下文窗口，同时仍然可以访问你所有的文件。

<Tip>
关注聊天界面中的**上下文仪表**。当它显示高使用量（橙色/红色）时，考虑启动新会话。
</Tip>

## 何时创建新会话

<CardGroup cols={2}>
<Card title="达到 Token 限制" icon="gauge-high">
上下文仪表显示高使用量 - 启动新会话给 Agent 完整的上下文容量。
</Card>

<Card title="并行工作" icon="code-branch">
让 Agent 同时处理独立的部分（后端 API + 前端 UI）。
</Card>

<Card title="不同方法" icon="route">
在不丢失原始对话的情况下尝试替代方案。
</Card>

<Card title="不同 Agent" icon="robot">
一个任务使用 Claude Code，另一个使用 Gemini CLI。
</Card>
</CardGroup>

## 何时不应该创建新会话

- **继续相关工作** - 如果 Agent 需要早期消息的上下文，继续使用同一个会话
- **提供反馈** - 使用同一个会话告诉 Agent 要修复什么
- **小的后续请求** - "再加一个加载动画"属于当前会话

<Warning>
新会话不会继承对话历史。新的 Agent 不会知道之前会话中发生了什么，除非你再次解释或它读取文件变更。
</Warning>

<Info>
工作空间中的所有会话共享相同的仓库和 Git 状态。一个会话做出的变更对其他会话可见。
</Info>

## 创建新会话

<Steps>
<Step title="打开会话下拉菜单">
  点击聊天工具栏中的会话下拉菜单（显示"最新"或会话名称）。
</Step>

<Step title="点击新建会话">
  从下拉菜单中选择 **+ 新建会话**。

  <Frame>
  <img style={{maxHeight: "300px"}} src="/images/workspaces-create-new-session.png" alt="会话下拉菜单显示新建会话选项和现有会话列表" />
  </Frame>
</Step>

<Step title="开始你的对话">
  新会话以全新的对话打开。描述你希望 Agent 处理的内容。

  <Tip>
  如果相关，提供关于其他会话中已完成工作的上下文。Agent 无法访问其他会话的对话。
  </Tip>
</Step>
</Steps>

## 在会话之间切换

要切换到不同的会话：

1. 点击聊天工具栏中的会话下拉菜单
2. 选择你想要切换到的会话

下拉菜单显示：
- **会话名称** - 基于初始任务或自动生成
- **最新**指示器 - 显示哪个会话最近活跃

<Note>
切换会话不会中断任何正在运行的 Agent 进程。每个会话的 Agent 继续独立工作。
</Note>

## 会话状态

会话可以处于不同的状态：

| 状态 | 描述 |
|------|------|
| **运行中** | Agent 正在活跃处理并进行变更 |
| **空闲** | 等待你的输入 |
| **需要关注** | Agent 正在等待审批或有疑问 |

工作空间侧边栏根据其会话显示整体的工作空间状态。

## 管理会话

### 重命名会话

会话根据初始任务描述自动命名。目前，会话名称无法手动更改。

### 查看会话历史

每个会话维护完整的对话历史。在对话面板中向上滚动查看早期消息和 Agent 操作。

### 停止 Agent

如果 Agent 在当前会话中运行：

1. 点击导航栏中的**停止**按钮，或
2. 使用键盘快捷键停止执行

<Warning>
停止 Agent 可能会使变更处于不完整状态。检查变更面板查看修改了什么。
</Warning>

## 会话中使用多个 Agent

不同的会话可以使用不同的 Agent：

1. 创建新会话
2. 在发送消息之前从 **Agent** 下拉菜单中选择不同的 Agent
3. 每个会话记住它使用的 Agent

<Tip>
使用专业的 Agent 处理不同的任务 - 例如一个 Agent 处理后端工作，另一个处理前端变更。
</Tip>

## 会话最佳实践

### 何时创建新会话

- **任务复杂度** - 将复杂任务分解为更小的会话
- **Token 限制** - 对话变得很长时启动新会话
- **不同方法** - 在不丢失进度的情况下尝试替代方案
- **并行工作** - 让 Agent 同时处理独立的部分

### 保持会话有序

- **每个会话一个焦点** - 让每个会话专注于特定目标
- **使用工作空间笔记** - 记录哪个会话做什么
- **切换前审查** - 切换会话前检查变更面板

## 解决会话之间的冲突

当多个会话对相同文件进行变更时：

1. 变更面板显示跨会话的所有修改
2. 提交前仔细审查变更
3. 使用行内注释功能标记需要注意的区域

<Note>
Git 自动处理大多数冲突。对于复杂的冲突，请参阅 [Git 操作](/workspaces/git-operations)。
</Note>
